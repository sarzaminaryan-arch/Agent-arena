# برگهٔ تحویل — خط لولهٔ دادهٔ ۴۸۳ شهرستان (۱۴۰۵/۰۷/۱۰)

این فایل را به هر دستیار/جلسهٔ تازه بدهید تا بدون توضیح دوباره، کار را ادامه دهد.

## ۱. هدف

برای هر ۴۸۳ شهرستان ایران یک مقالهٔ کامل در sarzaminaryan.ir وجود داشته باشد. بخش عددی و
ساختاریافتهٔ مقاله (جمعیت، مساحت، مختصات، تقسیمات، همسایه‌ها، اقلیم، جاذبه‌ها…) نباید دستی
تایپ شود؛ از ویکی‌داده و ویکی‌پدیای فارسی برداشت، پاک‌سازی و اعتبارسنجی می‌شود و بعد با
یک دکمه در پیشخان وردپرس روی نوشته‌ها می‌نشیند. نویسنده فقط «روایت» را می‌نویسد.

## ۲. مخزن و شاخه

- مخزن: `https://github.com/sarzaminaryan-arch/Agent-arena`
- شاخهٔ کاری (همه چیز روی همین است): `arena/01a0fcfc-agent-arena`
- انتشار قالب: `https://github.com/sarzaminaryan-arch/Agent-arena/releases` — نسخهٔ این ادامه **v2.8.9** (نتیجهٔ انتشار را در Releases بررسی کنید)
- مخزن قدیمی `sarzaminaryan-arch/S.A.1` **منسوخ** است (روی 2.5.0 مانده). `Update URI` از نسخهٔ ۲.۸.۳ به `Agent-arena` اصلاح شده است.

## ۳. اتصال وردپرس (مهم‌ترین بخش)

1. **توکن گیت‌هاب**: یک توکن ریزدانه با دسترسی *Repository contents: Read-only* روی
   `Agent-arena`. یا در `wp-config.php`:
   `define('SA_GITHUB_TOKEN', 'github_pat_…');`
   یا در پیشخان: نمایش ← به‌روزرسان گیت‌هاب (گزینهٔ `sa_github_updater_token`).
   همین توکن هم برای به‌روزرسانی قالب و هم برای دریافت داده استفاده می‌شود.
2. **قالب فرزند** `sarzaminaryan-child` باید ≥ **2.8.9** باشد (پیشخان ← به‌روزرسانی‌ها).
3. **ورود داده**: پیشخان ← **سرزمین آریان ← پوشش ۴۸۳ شهرستان** ← کادر بالای صفحه
   «دریافت خودکار داده از گیت‌هاب» ← استان را انتخاب کنید ← تیک «فقط پیش‌نمایش» را
   **بردارید** ← «دریافت و اعمال». قالب فایل
   `content/data/export/<province>.meta.json` را از شاخهٔ بالا می‌خواند و فقط خانه‌های
   **خالی** را پر می‌کند.
   - تیک «بازنویسی خانه‌های پرشده» فقط وقتی لازم است که مقدار قبلی غلط باشد.
   - اگر ستون «نساخته» عدد دارد، اول «ساخت پیش‌نویس‌های جاافتاده» را بزنید.
4. **راه دوم (SSH/WP-CLI)**: `wp sa-county import content/data/export/fars.meta.json [--force] [--dry-run]`
5. **راه سوم (بدون توکن)**: محتوای همان فایل JSON را در کادر «ورود دستی» بچسبانید.
6. شاخهٔ دادهٔ پیش‌فرض در قالب `arena/01a0fcfc-agent-arena` است؛ با
   `define('SA_GEO_DATA_REF', '…')` یا فیلتر `sa_county_data_ref` قابل تغییر است.

## ۶. هشدارها و تله‌ها

1. **ستون «پیشرفت» ≠ دادهٔ پرشده.** در صفحهٔ پوشش، ستون «مقاله‌ها» درصد نوشته‌های
   *منتشرشده* است و ورود داده آن را تکان نمی‌دهد؛ اثر ورود داده در ستون آبی «دادهٔ پرشده» دیده می‌شود.
2. **پیش‌فرض فرم «فقط پیش‌نمایش» است.** اگر تیک را برندارید هیچ‌چیز ذخیره نمی‌شود.
3. **هرگز مقدار دستی بازنویسی نمی‌شود** مگر با تیک «بازنویسی». در پرونده‌های حقیقت،
   `status: verified|manual` حتی با برداشت دوباره هم دست‌نخورده می‌ماند.
4. **جمعیت ویکی‌پدیا بی‌اعتبار است** (گاهی `1` یا شمارهٔ پانویس). مرجع جمعیت = ویکی‌داده
   با تاریخ؛ جمعیتِ بدون سال سرشماری عمداً دور ریخته می‌شود.
5. **اقلیم/زبان/معیشت/بهترین زمان سفر پیش‌نویس برآوردی‌اند** (سطح استان)، نه پژوهش شهرستانی.
6. **همسایه‌ها تقریبی‌اند** (گراف گابریل روی مختصات مراکز) — پیش از انتشار بازبینی شوند.
   قالب نامک همسایه را خودکار به لینک تبدیل می‌کند؛ قالب نوشتن: `dena - شمال`.
7. **فاصله تا مرکز استان خط مستقیم است، نه جاده.**
8. `gh workflow run` برای ربات ۴۰۳ می‌دهد و `gh run view --log` خطای `EOF` → برای شروع
   برداشت فقط `content/data/harvest-request.json` را عوض و پوش کنید؛ برای دیدن نتیجه
   `gh run view <id> --json status,conclusion` و فایل‌های کامیت‌شده.
9. **ورک‌فلو خودش روی شاخه کامیت می‌کند** → قبل از هر پوش:
   `git fetch origin arena/01a0fcfc-agent-arena`؛ درخت تمیز را با `git merge --ff-only FETCH_HEAD` به‌روز کنید.
   اگر تغییر محلی دارید، ابتدا آن را بررسی/کامیت کنید؛ هرگز reset مخرب یا force-push نکنید.
   هرگز force-push نکنید.
10. هر پوش به `content-templates/tools/geo/**` ورک‌فلوی برداشت را دوباره اجرا می‌کند (~۸ دقیقه).
11. **نیم‌فاصله** در ترمینال دیده نمی‌شود (`سی‌سخت` → `سیسخت`) — خرابی نیست، «درستش» نکنید.
12. اگر زیرمنویی در پیشخان دیده نشد، اول `show_in_menu` آن CPT را ببینید (همهٔ CPTها زیر منوی
    «سرزمین آریان» هستند، نه زیر `edit.php?post_type=city`).
13. REST وردپرس برای CPT `city` خاموش است (`show_in_rest=false`) → برای بررسی وضعیت سایت
    قابل استفاده نیست؛ از خروجی XML یا خود پیشخان استفاده کنید.
14. نامک‌های دادهٔ ما همیشه با نامک نوشتهٔ سایت یکی نیست؛ از ۲.۸.۶ به بعد نوشته از روی
    **عنوان** («شهرستان فلان») هم پیدا می‌شود. اگر باز هم «شهرستان بدون نوشته» دیدید،
    یعنی آن نوشته واقعاً وجود ندارد.

## ۷. منابع داده

- ویکی‌داده (SPARQL، کلاس `Q137535`): جمعیت دارای تاریخ `P1082`، مساحت `P2046`، مختصات `P625`،
  ارتفاع `P2044`، مرکز `P36`. نکته: `P47` (هم‌مرزی) برای شهرستان‌های ایران تقریباً خالی است.
- ویکی‌پدیای فارسی (`action=query&prop=revisions`): تقسیمات کشوری، مساحت، آب‌وهوا، فهرست جاذبه‌ها.
- فهرست رسمی ۴۸۳ شهرستان: `fa.wikipedia.org/wiki/شهرستان‌های_ایران` (تیر ۱۴۰۳) + اصلاح دستی خراسان رضوی.

## ۹. ادامهٔ ۱۴۰۵/۰۷/۱۰ — مرحلهٔ جاذبه‌ها

- کارهای شاخهٔ قبلی با merge به شاخهٔ همین نشست منتقل شدند؛ صادرات XML جدید کاربر حفظ شد.
- `harvest_poi.py` + آزمون‌های آفلاین: فقط چهار فیلد خالی جاذبه، با URL/نسخه/بخش منبع.
- `sources: "poi"` آمار و اقلیم/زبان/معیشت را دوباره برداشت یا برآورد نمی‌کند.
- خطای ERROR اعتبارسنجی مانع خروجی و کامیت داده می‌شود؛ WARNها برای بازبینی باقی می‌مانند.
- گزارش نتیجهٔ واقعی: `content/data/COUNTY-POI-PASS4.md`؛ صرف داشتن فهرست به معنی تأیید همهٔ جاذبه‌ها نیست.
- مرحلهٔ باقی‌مانده پس از این بسته: روستا/تقسیمات از منبع رسمی، مساحت‌های ناقص، همسایه از مرز واقعی.
- شاخهٔ قدیمی برای مرجع باقی است؛ تمام تغییرات و pushهای این نشست فقط روی
  `arena/01a0fcfc-agent-arena` انجام می‌شود.
