برداشت سراسری انجام شد؛ برای هر ۴۸۳ شهرستان یک پروندهٔ داده در `content/data/counties/<slug>.json` ساخته شد:

|---|---|

اعتبارسنجی: **۰ خطا**، ۱۴۵ هشدار (عمدتاً اختلاف جزئی ویکی‌دیتا و ویکی‌پدیا در مساحت).

## گام ۱ — فایل استان را بردارید

برای هر استان یک فایل آمادهٔ ورود ساخته می‌شود:

```
content/data/export/<province>.meta.json
```

نشانی خام برای کپی مستقیم (نمونهٔ کهگیلویه و بویراحمد):

```
https raw.githubusercontent.com/sarzaminaryan-arch/Agent-arena/arena/01a0f95f-agent-arena/content/data/export/kohgiluyeh-boyer-ahmad.meta.json
```

نام‌های استان‌ها همان نامک‌های سایت‌اند: `isfahan`، `fars`، `razavi-khorasan`، `tehran`، `gilan`، …

## گام ۲ — در پیشخان بچسبانید

**سرزمین آریان ← — پوشش ۴۸۳ شهرستان ← ورود انبوه داده**

۱. کل محتوای فایل JSON را در کادر بچسبانید.
۲. اول با تیکِ **«فقط پیش‌نمایش»** دکمهٔ «اعمال» را بزنید → گزارش می‌گوید چند خانه نوشته می‌شود، کدام‌ها رد می‌شوند (چون پر هستند) و کدام شهرستان نوشته ندارد.
۳. اگر گزارش درست بود، تیک پیش‌نمایش را بردارید و دوباره «اعمال».

قاعده‌های ایمنی که در خود ابزار سفت شده‌اند:

- فقط کلیدهای متای شناخته‌شده نوشته می‌شوند (`sa_cty_*` و `sa_city_latitude/longitude/elevation`).
- فقط روی نوشته‌ای که نامکش در فهرست رسمی ۴۸۳تایی است.
- **خانهٔ پرشده بازنویسی نمی‌شود** مگر تیک «بازنویسی خانه‌های پرشده» را بزنید؛ یعنی هر چیزی که خودتان نوشته‌اید در امان است.

اگر SSH دارید، همین کار با یک دستور:

```bash
wp sa-county import content/data/export/fars.meta.json --dry-run
wp sa-county import content/data/export/fars.meta.json
```

## گام ۳ — نتیجه را ببینید

روی صفحهٔ هر شهرستان بلافاصله اینها ظاهر می‌شوند (خانهٔ خالی چاپ نمی‌شود):

- کارت «اطلاعات کلیدی»: مرکز شهرستان، جمعیت با سال سرشماری، مساحت، اقلیم، فاصله تا مرکز استان
- دکمهٔ «مشاهده روی نقشه» از مختصات
- بخش «تقسیمات شهرستان» (بخش/دهستان/شهر/روستا)
- اسکیمای `AdministrativeArea` با `geo` و `containedInPlace` در JSON-LD

در صفحهٔ «پوشش ۴۸۳ شهرستان» هم درصد تکمیل پروفایل هر شهرستان بالا می‌رود.

## گام ۴ — برداشت دوباره هر وقت لازم شد

لازم نیست چیزی روی سیستم خودتان نصب کنید. فایل زیر را در گیت‌هاب ویرایش و ذخیره کنید:

```json
content/data/harvest-request.json
{ "province": "all", "sources": "both", "stubs": false }
```

با هر ذخیره، ورک‌فلوی **Harvest county data** اجرا می‌شود: برداشت → ادغام → اعتبارسنجی → ساخت فایل‌های ورود، و نتیجه را در همین مخزن کامیت می‌کند. گزارش پوشش و خطاها در تب Actions (بخش Summary) و در دو فایل زیر دیده می‌شود:

- `content/data/COUNTY-FACTS-COVERAGE.md` — ماتریس ستون × استان
- `content/data/COUNTY-FACTS-ISSUES.md` — خطاها و هشدارها

`province` می‌تواند `all` یا نامک یک استان باشد؛ `sources` یکی از `both` / `wikidata` / `wikipedia`؛ `stubs: true` اسکلت مقاله‌ها را هم در `content/cities/` می‌سازد.

## چه چیزی از کجا می‌آید (و چرا قابل‌دفاع است)

| ستون | منبع اصلی | یادداشت |
|---|---|---|
| جمعیت + سال | ویکی‌دیتا (گزارهٔ جمعیت با تاریخ) | سال میلادی خودکار به شمسی تبدیل می‌شود (۲۰۱۶ → ۱۳۹۵)؛ **جمعیت بدون سال اصلاً ذخیره نمی‌شود** |
| مختصات، مرکز، ارتفاع | ویکی‌دیتا | |
| مساحت، بخش، دهستان، شهر | جعبهٔ اطلاعات ویکی‌پدیای فارسی | اختلاف با ویکی‌دیتا در `conflicts` ثبت و در گزارش هشدار داده می‌شود |
| روستا، همسایه، جاذبه‌ها | هنوز خالی | گام بعدی: مرکز آمار/وزارت کشور برای روستا، مرز جغرافیایی برای همسایه، OpenStreetMap برای جاذبه |

هر مقدار در پروندهٔ شهرستان با `source`، `url` و `fetched` ذخیره شده است. اگر خودتان مقداری را در پیشخان اصلاح کردید، در پروندهٔ داده آن ستون را `"status": "verified"` کنید تا هیچ برداشت بعدی آن را بازنویسی نکند.

## ترتیب پیشنهادی کار

۱. **۱۵۳ مقالهٔ منتشرشده اول** — این‌ها ترافیک دارند؛ ورود داده برای استان‌هایی که مقالهٔ منتشرشده دارند، سریع‌ترین سود را می‌دهد.
۲. بعد استان‌های پرتقاضا: فارس، خراسان رضوی، اصفهان، مازندران، گیلان.
۳. موازی با آن: برداشت ستون‌های باقی‌مانده (روستا، همسایه، جاذبه) و بعد نگارش دسته‌ای ۵تایی روی دادهٔ آماده.
